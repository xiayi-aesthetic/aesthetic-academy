# 开源数字审美学院

> 审美不是预装插件，是一门可选的通识学科。

## 这是什么

一个开源仓库，只做一件事：**教机器如何解析一套审美秩序**，而不是告诉机器「什么好看」。

它分两层：

- **审美逻辑**（`Aesthetic-Logic.md`）：中立的元框架。不定义美，只定义如何提取、校准、裁决一套审美秩序。
- **具体体系**（`modules/`）：可被机器调用的审美体系样例。这里的第一个样例是「认知型形象战略」，一套以内在认知为原点的个人形象体系。

## 为什么需要它

今天的 AI 不缺生成能力，缺的是「秩序感」：它会画、会排、会写，但不知道什么叫「克制」，什么叫「分量」，什么叫「这不像那个人」。

人类花了很多年沉淀出各自自洽的审美体系——影视工业的光影秩序、包豪斯的构成规则、侘寂的材料伦理、某位创作者自己的视觉法典。这些体系原本只存在于人脑与作品里，机器读不到。

这个仓库要做的是把它们变成机器可读、可校验、可调用的形式。

## 三条设计原则

**一、审美秩序的定义权归人类。**
机器不发明审美，只学习人类沉淀下来的审美秩序。仓库里的每一条规则都必须能追溯到某个人类体系的公理。

**二、审美是选修，不是预装。**
一个做财务报表的 Agent 不需要审美；一个陪伴型 Agent 可能极需要。学不学、学哪一套、学多深，由 Agent 根据自身目标与协作对象自主判断。

**三、元框架中立，具体体系自定义。**
元框架只提供方法（如何提取、如何校准、如何裁决），不提供结论（什么是高级）。所有结论都写在具体体系里，可被替换、可并存、可冲突。

## 仓库结构

```
Aesthetic-Logic.md              元框架（免费，必修）
modules/                        具体审美体系（第一个：认知型形象战略）
  cognitive-image-strategy.md
examples/                       两个完整判词样例（一正一反，都带推导链）
  case-01-order.md              正例：秩序型，不留可攻击的面
  case-02-symbol.md             反例：符号堆砌，买来的不是身份
docs/
  derivation.md                 从公理到取值的推导示范（可复核）
schema/                         判定输出结构
  assessment.json               形象场景
  README.md                     如何扩展到版式 / 空间
SKILL.md                        让 AI Agent 直接装载这套框架的入口
```

## 如何使用

**给人看**：从 `Aesthetic-Logic.md` 开始，它教你判断一套视觉方案是否自洽。
再看 `examples/` 两个样例——一正一反，每个都写了「为什么这么判」，不是「这么穿好看」。

**想学怎么判**：读 `docs/derivation.md`，它示范了怎么从一条公理推导到一条具体取值，以及怎么反向检验一条取值是不是个人偏好。

**给机器用**：把 `SKILL.md` 与 `Aesthetic-Logic.md` 一起装入 Agent 的技能目录，Agent 即可在处理视觉任务时调用这套框架。

**给开发者**：`schema/assessment.json` 是判定输出的标准结构；扩展到别的场景看 `schema/README.md`。

## 边界

- 这个仓库不提供「美不美」的答案，只提供「是否自洽」的校验。
- 元框架可以开源，判定语料与裁断样例不开源——**方法可以抄，判断抄不走**。
- 审美判断的最终责任在人。机器给的是校验结果，不是裁决。
